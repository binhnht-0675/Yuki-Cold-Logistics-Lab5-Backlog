# バックログ JSON の形式

ファイルは項目の配列（または `{"items": [...]}`）。1 項目 = 1 issue。

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `key` | 文字列 | ○ | 安定キー（例 `E02-I03-S02`）。本文の `<!-- backlog-key: … -->` になる。重複不可。使える文字は英数字と `.`・`_`・`-` だけ（ほかは exit 2） |
| `level` | `epic` / `story` / `task` | ○ | 作成順（epic → story → task）と本文の「種別」 |
| `parentKey` | 文字列 / null | | 親のキー。親の level は子より上であること。1 親あたり子は 100 件まで（GitHub の上限） |
| `titleJa` | 文字列 | ○ | issue タイトル |
| `labels` | 文字列配列 | | そのまま issue ラベル。ない場合は自動作成（接頭辞 `種別:` / `層:` / `制約:` で色分け） |
| `assigneeRole` | 文字列 / null | | Project の `担当（仮）`（単一選択）に入る仮の役割。実在のアカウントではない |
| `layer` | 文字列 / null | | 本文末尾に表示（DB / API / UI / テスト など） |
| `bodyJa` | オブジェクト | | 本文。下表 |
| その他（`constraint2024`, `gapRefs`, `screen` など） | | | 読み飛ばす（ラベルで表現する） |

`bodyJa`:

| キー | 型 | 本文での出し方 |
|---|---|---|
| `概要` | 文字列 | 段落 |
| `対象FT` | 文字列配列 | 見出し「対象機能（FT）」、読点区切り |
| `参照` | `{path, section}` の配列 | permalink かテキスト（`--ref-style`） |
| `規模の手がかり` | 文字列 | 段落（見積もりの根拠になる数） |
| `完了の定義` | 文字列配列 | チェックボックス |
| `依存` | キー配列 | 作成済みなら `#番号（キー）`、未作成ならキーのみ（`update-body` で後から置換） |
| `備考` | 文字列 | 段落（空なら出さない） |
| 上記以外 | 任意 | キー名を見出しにして末尾に出す |

空の値（null・空文字・空配列）の節は出さない。

検証（`plan` / `apply` の前に必ず実行、エラーは exit 2）: キー重複、level 不正、タイトル空、
親が存在しない、親の level が子以下、子が 100 件超。
